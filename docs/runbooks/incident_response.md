# 事件响应与回滚运行手册

## 凭据事件

1. 暂停外部入口，保持数据库、Redis 和对象存储可供取证与恢复。
2. 在凭据提供方撤销受影响的 Key 或 Token。
3. 生成新的 Secret 文件，目录权限设为 0700、文件权限设为 0600。
4. 只重建依赖该 Secret 的服务。
5. 验证新凭据有效且旧凭据失败；只记录证据编号，不记录值、前后缀或可猜测哈希。
6. 检查安全审计、限流和对象访问日志，保留关联 ID 与规则编号。

如果真实 Secret 已进入 Git 历史，应立即停止普通提交和推送，先轮换凭据，再使用经过评审的历史清理流程处理所有引用；仅删除工作树文件不能消除历史暴露。

## 应用回滚

部署前记录提交 ID、镜像 digest、Compose 结构摘要和 Alembic revision。应用故障时先隔离外部流量，再切换到明确的旧镜像与非敏感配置。已执行的数据迁移优先使用 forward-fix，不直接对生产数据库 downgrade。

## 数据恢复

只向精确命名的隔离数据库或 bucket 恢复并先校验 SHA-256。不得覆盖开发/生产对象，不得 drop 主库，也不得使用通配符清理。恢复验证完成并经过人工批准后，才制定面向目标环境的数据切换步骤。
